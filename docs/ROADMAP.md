# Роадмап

Каждая фаза заканчивается работающим инструментом, которым можно пользоваться. Внутри фазы работа идёт по циклу spec → plan → implement → verify.

## Фаза 1 — скелет: демон, tmux, worktree

**Цель:** `rocket` умеет поднять агента в изолированном worktree и управлять сессиями руками.

- Go-модуль, каркас CLI (cobra) и демона; автозапуск демона, PID/сокет, `daemon start|stop|status|run`.
- SQLite-store + миграции; журнал событий (запись + `rocket events`).
- Реестры в базе: `repo add|ls|rm` (локальные чекауты), `project create|ls|show|link|unlink|rm` (main + linked).
- Runtime tmux: create/inject/capture/alive/destroy, exact-match, keep-alive shell, launch-скрипты.
- Workspace worktree: create/restore/destroy, symlinks, post_create, коллизии веток.
- Адаптер claude-code (launch + env; активность — в фазе 2).
- Команды: `spawn` (пока без проверки «только оркестратор»), `ls`, `attach`, `kill`, `restore`, `doctor`, `logs`.
- Реконсиляция при старте демона (store vs tmux/файлы).

**Готово, когда:** `rocket repo add … && rocket project create … && rocket spawn … && rocket attach …` даёт живого Claude Code в worktree; `kill --cleanup` корректно всё сносит; демон переживает рестарт.

## Фаза 2 — активность и сообщения

**Цель:** надёжный `rocket send` и честные статусы в `rocket ls`.

- Монитор активности: каскад поллинга (процесс/TTY, JSONL Claude Code), пороги, события `activity_changed`.
- Push-канал: hook-скрипты в worktree → `POST /v1/internal/activity`.
- Очередь сообщений: таблица, пер-получатель FIFO-доставщик, инжекция с подтверждением, ретраи, `failed`, история.
- `rocket send` (+ `--file`, `--wait`), `GET /v1/messages`.
- SSE `/v1/events/stream`.

**Готово, когда:** два вручную заспавненных агента устойчиво переписываются через `rocket send`, включая случай «получатель занят 10 минут»; статусы в `ls` соответствуют реальности.

## Фаза 3 — задачи и оркестраторы

**Цель:** основной сценарий продукта — задача на канбане, оркестратор ведёт её через несколько проектов и отчитывается в неё.

- Слой задач: таблицы tasks/task_docs/task_log, API, `rocket task add|ls|show|start|move|doc|log|cancel`.
- `rocket up` (task add + start): slug, worktree в хабе, системный промпт + kickoff (шаблоны, переопределение файлом).
- `rocket spawn` — только для оркестраторов, проверка «репо ∈ проект оркестратора», `parent_id`, наследование `feature_slug`, системный промпт воркера; автосоздание подзадачи, `--subtask`.
- Автопереходы статусов подзадач (spawn → in_progress; PR-переходы — заглушки до фазы 4).
- `rocket status <slug>`; `kill --cascade`; `attach <task-id>`.
- Heartbeat: только задачи в `in_progress`, детект застрявших воркеров, сводки оркестратору, анти-спам.

**Готово, когда:** реальная фича с 2+ воркерами в 2 проектах доведена до PR только через оркестратора; в `task show` видна декомпозиция, спека, решения и проблемы; зависший воркер разбужен после heartbeat.

## Фаза 4 — GitHub

**Цель:** демон видит PR/CI и закрывает петлю доставки.

- GitHub-токен (`rocket github auth`, settings в базе), REST-клиент, `GH_TOKEN` в env сессий.
- Каталог репозиториев GitHub + клонирование: `repo add --github`, `GET /v1/github/repos`.
- Поллер: поиск PR по ветке, `pr_state`/`ci_state`, события.
- Реакции: CI failing → сообщение воркеру; changes requested → сообщение воркеру.
- Авто-cleanup воркера после merge (grace, ветка остаётся, off-switch per-project).
- Автопереходы подзадач: PR открыт → review, PR смержен → done.
- PR/CI-колонки в `ls`/`status`/`task show`.

**Готово, когда:** merge PR воркера сам приводит к его зачистке и переводу подзадачи в done; красный CI сам возвращает воркера в работу.

## Фаза 5 — мульти-агент

**Цель:** оркестратор и воркеры могут быть разными агентами.

- Финализация интерфейса `Agent`, адаптер codex (launch, активность), `--agent` per-spawn, `defaults.agent`.
- `doctor` проверяет все настроенные агенты.

**Готово, когда:** воркер на codex проходит полный цикл (спавн → PR → merge → cleanup) под оркестратором на claude-code.

## Фаза 6 — дашборд

**Цель:** наблюдение и управление из браузера. Дизайн — [11-dashboard.md](11-dashboard.md).

- `web/` (TS + React + Vite), статика раздаётся демоном; данные — REST + SSE.
- Проекты: переключатель, визард создания (main/linked из GitHub-каталога или локального пути), Settings с GitHub-токеном.
- Экран «Канбан»: колонки, живые карточки, drag-n-drop move, создание задач, Start.
- Экран «Карточка задачи»: overview с декомпозицией, docs, journal, messages (чат с оркестратором), рейл сессий с term/attach/kill.
- Встроенный терминал: WS `/v1/sessions/{id}/term` в демоне (tmux attach в PTY) + xterm.js-панель в карточке задачи.
- Экран «Система»: сессии/процессы/worktree/очередь, kill/cleanup.

**Готово, когда:** полный цикл фичи (создать задачу → назначить оркестратора → наблюдать → пообщаться с оркестратором в встроенном терминале → принять в done) проходит из браузера, вообще не открывая локальный терминал.

## За горизонтом (не обещания)

Нотификации (macOS/Telegram), терминал в браузере, MCP-транспорт сообщений вместо инжекции, шаблоны фич, метрики/стоимость агентов.
