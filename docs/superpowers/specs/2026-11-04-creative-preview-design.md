Final concise design for 5990:
- Dedicated preview-only listener configured with preview_host, preview_port, preview_public_url; no tunnel changes. Require a different hostname from Rocket and a remotely reachable HTTPS preview origin for an HTTPS dashboard; disabled/missing configuration yields actionable unavailable status.
- Authenticated Rocket API POST/GET /v1/creative/previews binds {run_id,stage_id?,item_id?,port} using core ResolveCreativeContext and same-project agent checks; DELETE /v1/creative/previews/{id} revokes. Store registration plus unguessable capability; access links returned only by authenticated context lookup.
- Separate origin proxies /p/<capability>/ to the registered loopback port. Preserve prefix; agents launch a base-path-aware server (e.g. Vite --base). No HTML/JS rewriting or arbitrary-app claim. Modules/storage work; external absolute localhost URLs and apps ignoring the base path are unsupported.
- Operator-configured preview_ports allowlist restricts registration; exclude Rocket API/TLS/preview ports. No arbitrary URL/host input. Agent owns launch/runtime.
- Strip Cookie/Authorization/X-Rocket-* in both relevant directions, deny Rocket API paths, enforce sandbox CSP allowing scripts/forms/same-origin but no top navigation; referrer=no-referrer, cache=no-store. Unknown capability 404; stopped/revoked or failing upstream visibly unavailable (502).
- Dashboard receives {id,run_id,stage_id?,item_id?,status:ready|unavailable,url?,base_path,message?}; same URL for iframe and separate tab, iframe sandbox="allow-scripts allow-forms allow-same-origin" and new tab noopener/noreferrer. HTTP probe determines current upstream availability, never treats 5xx as ready.
- Focused Go store/API/proxy tests (incl. actual httptest server, credentials/isolation, context validation, stopped upstream, assets and WS); no generated project, public deployment or live daemon restart.
Alternatives: same-origin proxy rejected for privileged-origin exposure/rewriting; per-preview public ports rejected for remote forwarding complexity. Explicit prefix-aware isolated origin is the smallest bounded implementation. No departure from approved scope.
