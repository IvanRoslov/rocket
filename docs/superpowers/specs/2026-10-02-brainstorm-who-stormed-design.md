# Метрика брейншторма: каждая задача и кто штормил (task #5019)

## Коротко

**Что строим.** Метрика брейншторма перестаёт видеть только ответы Ивана. Каждый ответ на вопрос шторма считается тому, кто его дал: Ивану или агенту (cto или другому по имени). По каждому шторму видно, кто штормил («Иван», «cto», «Иван + cto»). Недельная сводка разложена по участникам, поэтому «Иван соглашается с оркестратором» и «cto соглашается с оркестратором» никогда не складываются в одну цифру. Рядом с «кто штормил» показана реакция Ивана на гейт: «Go с 1-го раза», «Go после N правок» или «ждёт Go». «Правки» теперь считаются только до первого Go.

Всё это есть в CLI (`rocket stats brainstorm`), в API, в вебе (экран метрики и вкладка шторма задачи) и в мобильном приложении (вкладка шторма).

**Что сознательно не делаем.**
- Обычные вопросы-решения (не шторм) в метрику не попадают, как и раньше. Поэтому у #5009/#5010 будет 5 отвеченных cto, а не 7: два из семи ответов cto были на обычные вопросы.
- Экран метрики в мобильном приложении не появляется (его не было и в #4901).
- Отдельного счётчика «правки после Go» нет.
- Новой таблицы и миграции нет: всё считается на лету из уже записанных данных, ответы cto в прошлых штормах подхватятся сами.

## 1. Решения шторма

| # | Решение | Источник |
|---|---|---|
| Q1 | Каждый ответ считается своему автору. `answered_by` шторма — уникальный список участников в порядке первого ответа, в UI подпись через «+». Ответ, записанный оркестратором из терминала (`brainstorm record`), остаётся ответом человека. | cto |
| Q2 | Недельная строка — тройка (неделя, скилл, кто отвечал), где кто отвечал = `human` или id агента. `human` подписывается «Иван». | cto |
| Q3 | «Правок спеки» считаются только до первого Go, плюс признак «Go с 1-го раза». Гейт, снятый новой версией спеки (`superseded`), правкой не считается: учитываются только явные «нужны правки» (`changes`) от человека. На это нужен тест. | cto |
| Q4 | Экран метрики: над графиком переключатель участника. Выбор запоминается локально у зрителя. По умолчанию выбран Иван, а если у него нет ответов в окне — первый участник с ответами. Таблица штормов показывает все штормы, колонки «Кто штормил» и «Гейт» видны всегда. | cto |

## 2. Определения

- **Участник ответа** — автор последнего `answer`-сообщения треда шторма, нормализованный через `canonicalParticipant`: `""` превращается в `"human"`. Ответ засчитывается, если тред `resolved/answered`, у него есть `outcome` и есть автор. Других условий нет: фильтр «только человек» удаляется.
- **Порядок `answered_by` шторма** — по времени ответа (`resolved_at`, при равенстве — по id вопроса). Каждый участник встречается один раз.
- **Правки до Go (`spec_changes`)** — число гейтов задачи со статусом `changes`. Если Go был, считаются только решённые раньше первого Go (`decided_at < go_at`). Если Go не было, считаются все. `superseded` и `pending` не считаются.
- **Go с 1-го раза (`first_try_go`)** — `go_at != null && spec_changes == 0`.
- **Был ли гейт (`has_gate`)** — у задачи есть хотя бы один гейт в любом статусе. Без этого поля клиент не отличит «гейтов не было» от «гейт ждёт, правок 0».
- **Состояние гейта в UI** (выводится из `go_at` и `spec_changes`):
  - `go_at` и 0 правок → «Go с 1-го раза»;
  - `go_at` и N правок → «Go после N правок»;
  - без `go_at`, но гейты были → «ждёт Go (правок: N)»;
  - гейтов не было → «—».
- Недели, окно и правило попадания шторма в окно — без изменений (ISO-неделя ответа, локальное время демона).

## 2.1 Язык подписей (правка v3)

CLI говорит по-русски: «Иван», «Кто штормил», «Go с 1-го раза» и т. д., как в §3.3.

Веб и мобильный интерфейс целиком на английском, а человек там везде подписан как «you» (существующий `participantLabel` в `web/src/lib/participants.ts`). Чтобы не смешивать языки на одном экране, новые подписи в вебе и мобильном английские:
- человек — `you` (через существующий `participantLabel`), агент — по id;
- кто штормил — `Who stormed`, участники через « + » («you + cto»), «—», если ответов нет;
- «Правок до Go» — `Spec changes before Go` (переименование старого `Spec changes`);
- гейт — `Gate`: `Go first try`, `Go after N changes`, `awaiting Go (changes: N)`, `—`;
- закрытый вопрос шторма — `answered by cto`.

Русские подписи из §3.4 и §3.5 относятся к смыслу, а точный текст в вебе и мобильном — этот список.

## 3. Изменения по слоям

### 3.1 Store (`internal/store/brainstorm_stats.go`)

- `humanAnswer()` заменяется на `answerer() (string, bool)`, который возвращает канонического участника.
- `BrainstormWeek` получает `AnsweredBy string`. Ключ агрегации — (week, skill, answered_by). Сортировка: неделя ↑, скилл, затем `human` первым, остальные по алфавиту.
- `BrainstormCounts`: смысл `SpecChanges` меняется на «до первого Go».
- `BrainstormStorm` получает поля `FirstTryGo` и `HasGate`.
- `BrainstormStorm` получает:
  - `AnsweredBy []string` (порядок первого ответа);
  - `ByAnswerer []BrainstormAnswererCounts`: участник плюс счётчики answered/accepted/accepted_with_comment/corrected/wrong_turn в том же порядке;
  - общие счётчики шторма — сумма по всем участникам («каждая задача»).
- Подсчёт `SpecChanges` переносится после свёртки гейтов, потому что первый Go может прийти в выборке позже `changes`.

### 3.2 API (`internal/api/stats.go`, `docs/03-daemon-api.md`)

Изменения аддитивные: старые поля остаются, меняется только смысл `spec_changes`.

```json
{"weeks":[{"week":"2026-W40","skill":"orchestrator-brainstorming","answered_by":"cto",
           "answered":5,"accepted":5,"accepted_with_comment":0,"corrected":0,"wrong_turn":0}],
 "storms":[{"task_id":5010,"title":"…","project_id":"users","skill":"orchestrator-brainstorming",
            "questions":3,"answered":3,"accepted":3,"accepted_with_comment":0,"corrected":0,"wrong_turn":0,
            "answered_by":["cto"],
            "by_answerer":[{"answered_by":"cto","answered":3,"accepted":3,"accepted_with_comment":0,"corrected":0,"wrong_turn":0}],
            "spec_changes":0,"first_try_go":true,"has_gate":true,"go_at":1790926157}]}
```

- `GET /v1/tasks/{id}/brainstorm/stats` возвращает ту же строку шторма с новыми полями.
- `answered_by` и `by_answerer` — всегда массивы, пустые, если ответов нет.
- В `docs/03-daemon-api.md` (≈:194) правило «считаются только ответы человека» заменяется новыми определениями из §2.

### 3.3 CLI (`internal/cli/stats.go`)

- В недельной таблице после «СКИЛЛ» появляется колонка `КТО` («Иван» / id агента).
- В таблице штормов:
  - после «СКИЛЛ» появляется колонка `КТО ШТОРМИЛ` («Иван + cto»; «—», если ответов нет);
  - «ПРАВОК СПЕКИ» переименована в `ПРАВОК ДО GO`;
  - новая колонка `ГЕЙТ` с состоянием из §2;
  - «GO» (дата) остаётся.
- `--json` отдаёт поля API как есть.

### 3.4 Веб

- **Экран метрики `BrainstormMetricsScreen`:**
  - над графиком сегментный переключатель участников, у которых есть ответы в окне. Подписи «Иван» / id агента. Выбор хранится в `localStorage` (обёрнутом в try/catch), правило выбора по умолчанию — из Q4;
  - график строится по недельным строкам выбранного участника, серии по скиллам, как сейчас;
  - в таблице штормов колонки «Кто штормил» и «Гейт», «Правок спеки» переименована в «Правок до Go».
- **Вкладка шторма задачи `BrainstormTab`:**
  - у счётчиков появляются строки «Кто штормил: cto» и «Гейт: Go с 1-го раза» (или иное состояние);
  - если участников больше одного, счётчики показываются по каждому участнику.
- **`BrainstormResult`** (закрытый вопрос шторма) показывает «ответил: cto», если ответил не человек (поле `answered_by` треда уже приходит).
- Типы, MSW-фикстуры и тесты обновляются.

### 3.5 Мобильный (`mobile/src/components/BrainstormTab.tsx`)

- Добавляются те же строки «Кто штормил» и «Гейт», а также «ответил: cto» на закрытом вопросе.
- Типы и тесты обновляются.

## 4. Тесты (обязательные кейсы)

- **Store:**
  - ответ cto считается в шторме и в недельной строке `answered_by=cto`;
  - смешанный шторм (Иван + cto): `answered_by` в порядке первого ответа, `by_answerer` раздельно, общие счётчики — сумма;
  - `brainstorm record` (автор `human`) идёт как Иван;
  - `changes` после первого Go не считаются;
  - `superseded` не считается (тест из условия Q3);
  - без Go считаются все `changes`;
  - `first_try_go`;
  - legacy-автор `""` считается как `human`;
  - dismiss и reopen по-прежнему не считаются.
- **API:** форма JSON, пустые массивы.
- **CLI:** колонки и подписи.
- **Веб:**
  - переключатель: выбор по умолчанию, когда у Ивана нет ответов, и восстановление выбора из хранилища;
  - колонки таблицы;
  - строки вкладки.
- **Мобильный:** строки вкладки.
- **Проверка:** CI нет, оркестратор сам гоняет `make test`, `cd web && npm run build`, `cd mobile && npm test && npm run typecheck`. После мержа `rocket stats brainstorm` на живой базе показывает у #5009/#5010 «cto», отвечено 2 и 3, «Go с 1-го раза».
