# Механизм брейншторма оркестратора и его метрика — спека v2

**Коротко простыми словами.** Шторм оркестратора идёт во вкладке «Брейншторм» задачи: наверху проблема, дальше вопросы с рекомендацией агента, внизу Go / «Нужны правки» по версии спеки. Метрика качества рекомендаций считается из твоих ответов. **В v2:** вопросы шторма живут только во вкладке «Брейншторм» — их больше нет во вкладке «Вопросы» и во входящих; во входящих вместо них одна строка на шторм со ссылкой на вкладку. Не входит: журнал решений и сигнал расхождения от воркеров.

Задача #4901, майлстон #4900 «Брейншторм, который проходит на рекомендациях агента».
Все решения ниже — из шторма с Иваном 2026-10-01 (дословно в журнале задачи).

## Проблема

- Шторм живёт в терминале оркестратора и в разрозненных тредах — целиком его нигде не видно.
- «Го» — обычный вопрос go / needs changes; спека переписана → такой же вопрос заново.
- Качество рекомендаций агента не мерится (ощущение ~50/50) — улучшать скилл и доки вслепую.

## Цель и критерий успеха

Шторм — часть задачи с единым представлением (вкладка «Брейншторм» в вебе и мобильном), выход из шторма — отдельный механизм Go по версии спеки, а метрика качества рекомендаций получается из механизма сама. Успех: после нескольких штормов Иван видит долю принятых рекомендаций по неделям и развороты на шторм, не делая ничего сверх обычных ответов.

## Вне объёма (следующая история, cto уведомлён)

- Журнал задачи как decision-лог (фильтры «решение человека / агента / заметка», агенты пишут все решения).
- Сигнал расхождения «спека ≠ код» от воркеров.
- Изменения содержания скилла (это истории 3–4 майлстона).

## 1. Скилл и переключатель

- В репо rocket появляется скилл `orchestrator-brainstorming` — копия `superpowers:brainstorming` (SKILL.md и сопутствующие файлы: visual-companion.md, spec-document-reviewer-prompt.md, scripts/) без изменений по смыслу; меняется только имя в frontmatter и пути к собственным файлам. Источник копии — superpowers 6.4.1; версия-источник фиксируется в README скилла.
- Скилл встраивается в бинарь rocket. При подготовке рабочей папки оркестратора на claude-code rocket кладёт его в `<worktree>/.claude/skills/orchestrator-brainstorming/` (файлы не попадают в git — через `.git/info/exclude` или аналог, как остальные служебные файлы rocket). Глобальный `~/.claude` не трогается.
- Настройка «Кастомный брейншторм оркестратора» (`orchestrator_brainstorm_custom`, bool, по умолчанию выкл.) — в таблице settings, редактируется в разделе настроек веба (`GET/PUT /v1/settings`).
- При сборке промпта оркестратора (system prompt и kickoff) rocket подставляет имя скилла: `orchestrator-brainstorming` (вкл.) или `superpowers:brainstorming` (выкл.). Больше настройка ни на что не влияет.
- Воркеры всегда используют штатный `superpowers:brainstorming`; промпт воркера не меняется.
- При старте задачи в задаче запоминается, какой скилл шторма был выбран (`brainstorm_skill`). Метрика делит штормы по этому полю; переключение настройки посреди шторма на уже начатую задачу не влияет (при restore используется запомненное значение).

## 2. Шторм как сущность задачи

Один шторм на задачу. Механизм (вопросы, Проблема, гейт, метрика) работает одинаково при любом значении переключателя.

### 2.1 Документ «Проблема»

- Новый вид документа задачи `problem` (рядом с spec/plan/report/doc), версионируется так же (каждая запись — новая версия).
- Оркестратор пишет его первым шагом шторма: что болит, для кого, что будет успехом — простыми словами.

### 2.2 Вопрос шторма

- Существующий тред вопросов с типом `brainstorm` (рядом с decision/fyi). Ведёт себя как decision-тред (участники, очередь, ответы, входящие), плюс:
  - `recommended_option` — номер рекомендованного варианта (обязателен, если есть варианты);
  - `chosen_option` — номер выбранного варианта (NULL — ответ своим текстом);
  - `answer_comment` — комментарий человека к выбору (может быть пустым);
  - `answer_source` — `ui` | `terminal`;
  - `outcome` — `accepted` | `corrected` | `wrong_turn`;
  - `outcome_overridden` — исход вручную переопределён человеком.
- Создание: `rocket task ask <task> --brainstorm --title … --brief … --option … --option … --recommend N`. Без `--recommend` при наличии вариантов — ошибка.
- Ответ во вкладке: выбор варианта + необязательный комментарий, либо только свой текст. Сохраняются и номер варианта, и текст.
- Ответ из терминала: `rocket task brainstorm record <task>/Q<n> [--choose N] "<текст человека дословно>"`. Доступно оркестратору задачи только для тредов типа `brainstorm`; закрывает тред с `answer_source=terminal`. Это единственное исключение из правила «агент не закрывает треды»: агент записывает ответ человека, а не свой.
- Исход вычисляется автоматически при ответе:

  | Что сделал человек | Исход |
  |---|---|
  | выбрал рекомендованный вариант (с комментарием или без) | `accepted` (признак «с комментарием» — непустой `answer_comment`) |
  | выбрал другой вариант (с комментарием или без) | `corrected` |
  | не выбрал вариант, написал своё | `wrong_turn` |

- Человек может переопределить исход (UI, `PATCH`-эндпоинт; только человек) → `outcome_overridden=true`.
- Переоткрытие треда сбрасывает ответ и исход; новый ответ вычисляет их заново.

### 2.3 Выход из шторма (гейт)

- Новая таблица гейтов: задача, версия спеки, версия плана, статус `pending` | `go` | `changes` | `superseded`, комментарий, кто решил, когда запрошен/решён.
- `rocket task gate request <task>` (оркестратор) — после того как спека и план положены; фиксирует текущие последние версии spec и plan. Без спеки — ошибка.
- Новая версия спеки автоматически переводит ожидающий гейт в `superseded` (нужен новый запрос).
- Решение — только человек (запросы без агентской идентичности: дашборд, мобильный, собственный терминал человека); агентам и persistent-агентам — 403.
  - **Go** → статус задачи `brainstorm → in_progress` (как `rocket task move`, с записью в журнал), оркестратору доставляется сообщение «Go по спеке vN (план vM) — начинай».
  - **Нужны правки** (комментарий обязателен) → оркестратору доставляется комментарий; счётчик правок спеки шторма +1.
- Вопрос «Confirm spec … go / needs changes» в промптах заменяется на `rocket task gate request`; правило «любая правка спеки снова открывает гейт» реализуется механизмом.

### 2.4 Промпт оркестратора

Независимо от переключателя, раздел про шторм в промпте оркестратора (orchestrator.md + kickoff.md + docs/prompts):
- первым шагом — документ `problem`;
- каждая развилка, требующая решения человека, — `rocket task ask --brainstorm` с рекомендацией (`--recommend`); обсуждение может идти в терминале;
- если человек ответил в терминале — сразу `rocket task brainstorm record` с его текстом дословно;
- выход — `rocket task gate request`; переход в in_progress делает механизм по Go.

## 3. Интерфейс

### 3.1 Вкладка «Брейншторм» (веб и мобильный)

Сверху вниз:
1. Счётчики шторма: вопросов, принято (из них с комментарием), поправлено, ушли не туда, правок спеки.
2. «Проблема» — последняя версия документа `problem` (пустое состояние: «Проблема ещё не описана»).
3. Вопросы шторма по порядку: заголовок, brief, свёрнутые подробности, варианты-кнопки с отметкой ★ у рекомендованного, поле комментария, ответ своим текстом. После ответа: выбранный вариант, текст человека, исход (переключаемый), пометка «из терминала». Обсуждение внутри треда — как в нынешних тредах.
4. Блок выхода: «Ждём спеку» / «Спека vN · План vM» со ссылками и кнопками **Go** / **Нужны правки** (с полем комментария); история гейтов (v1 — правки «…», v2 — Go).

- Вкладка открывается по умолчанию, пока задача в статусе brainstorm; доступна и после.
- **(v2)** Вопросы шторма показываются **только** во вкладке «Брейншторм». Во вкладке «Вопросы» задачи их нет (веб и мобильный).
- **(v2)** Во входящих (веб и мобильный) вместо отдельных вопросов шторма — одна строка на задачу, пока в её шторме есть вопросы, ждущие человека: «Шторм #N «<название>»: ждут K вопросов» → открывает вкладку «Брейншторм» задачи. Строка учитывается в счётчике входящих как один элемент. Отвеченные вопросы шторма во входящих не показываются вовсе.
- **(v2)** Плашка ожидающего вопроса над задачей для вопроса шторма ведёт во вкладку «Брейншторм».
- Обновление живое: добавляются события шины для записи документа задачи и для изменений гейта; изменения вопросов уже публикуются.

### 3.2 Экран «Метрика брейншторма» (веб)

- График: доля принятых рекомендаций по неделям, отдельными рядами `orchestrator-brainstorming` и `superpowers:brainstorming`.
- Таблица штормов: задача (ссылка на вкладку), скилл, вопросов, принято / с комментарием / поправлено / ушли не туда, правок спеки до Go, дата Go.

### 3.3 CLI

`rocket stats brainstorm [--weeks N] [--json]` — то же, что экран: понедельная сводка и список штормов.

### 3.4 Настройки

В вебе — переключатель «Кастомный брейншторм оркестратора (orchestrator-brainstorming)».

## 4. Метрика — определения

- В метрику попадают только треды типа `brainstorm`; ответ с исходом — тот, у которого есть `outcome`.
- Доля принятых за неделю = `accepted` / (`accepted` + `corrected` + `wrong_turn`) по вопросам, отвеченным в эту неделю (ISO-неделя, локальное время daemon).
- Развороты на шторм = число `wrong_turn` в задаче. Правки спеки = число гейтов задачи в статусе `changes`.
- Считается на лету из данных (отдельного хранилища агрегатов нет). Старые задачи без brainstorm-тредов метрику не портят.

## 5. Обработка ошибок и граничные случаи

- `--recommend` вне диапазона вариантов → 400.
- `brainstorm record` для чужой задачи, не-brainstorm треда или уже закрытого треда → отказ с понятным текстом.
- Решение гейта агентом → 403; решение по `superseded`/уже решённому гейту → 409.
- Go при статусе задачи не brainstorm → гейт фиксируется как go, статус не трогается, в журнал — заметка.
- Codex-оркестратор: скилл в папку не кладётся (в промпте codex скиллы и так вырезаются); остальной механизм работает через CLI.

## 6. Тестирование

- Go: unit-тесты store (миграция, поля, исходы, гейты, supersede), API (права: человек/агент/persistent; record; override; Go → статус + доставка сообщения), рендер промптов (имя скилла по настройке, запомненное в задаче), раскладка скилла в worktree, подсчёт метрики.
- Web/mobile: тесты компонентов вкладки (рекомендация, комментарий, исход, гейт), экрана метрики, переключателя.
- Сквозная проверка вручную: задача со включённым переключателем → оркестратор стартует на `orchestrator-brainstorming`, вопросы видны во вкладке, Go переводит задачу и будит агента, `rocket stats brainstorm` показывает шторм.
