# Мобилка догоняет: чат и вопросы — дизайн

Дата: 2026-09-29. Статус: на ревью.

## Зачем

Мобильное приложение (`mobile/`, Expo) отстало от демона и веба:

1. **Чат сломан.** Сообщения, доставленные через сокет Claude Code (`socket_delivery`,
   `internal/socketmsg`), лежат в транскрипте в конверте
   `<cross-session-message from="…" from-name="X">\n…\n</cross-session-message>`.
   Мобилка считает их системным шумом (прячет, при показе — сырой XML); веб рисует их как
   собственный пузырь человека с тегами. Сохранённый текст ≠ отправленный, поэтому
   оптимистичный пузырь никогда не подтверждается и висит внизу ленты под более новыми
   ответами — «путается последовательность».
2. Мобилка не знает новых форматов инжектов (`[rocket …]`, `[#1023/Q2 reply from cto]`,
   `[SYSTEM NOTIFICATION - NOT USER INPUT]`) — они рисуются как сообщения человека; вызовы
   инструментов — сырым JSON.
3. **Нет общего раздела вопросов** (в вебе — `/questions` на `GET /v1/threads`). Вопросы в
   мобилке есть только внутри задачи и агента, без заголовка и с сырым markdown.

Чат с постоянными агентами в мобилке уже есть (кнопка «💬 Chat» на вкладке «Агенты» и на
экране агента) — он чинится вместе с п. 1, отдельной работы не требует.

**Критерий успеха:** в чате оркестратора и постоянного агента на телефоне нет служебных тегов,
сообщения человека и агентов стоят в порядке транскрипта, отправленное сообщение подтверждается
и не застревает внизу; вкладка «Вопросы» показывает все открытые вопросы, и на вопрос с
вариантами можно ответить одним нажатием с возможностью отмены.

## Принятые решения

| Вопрос | Решение |
|---|---|
| Где снимать конверт | В демоне, при чтении транскрипта — чинит и мобилку, и веб |
| Раздел вопросов | Отдельная вкладка «Вопросы» со счётчиком; «Система» переезжает в «Настройки» |
| Вид раздела | Лента карточек (не фокус-режим по одному) |
| Отмена ответа | Окно 5 с, как в вебе |

Вне объёма: фокус-режим и горячие клавиши веба, задавание новых вопросов с телефона,
push-уведомления, терминал, выбор типа агента (`/v1/agent-kinds`).

## Часть 1. Чат

### 1.1 Демон: разворачивать конверт

Где: `internal/agent/claudecode/chat.go`, `extractUserText` (или сразу после неё — там, где
собирается `ChatEntry{Role:"user"}`).

Правило: если текст user-записи целиком — один конверт `socketmsg.EnvelopeTag`
(`<cross-session-message …>\n<body>\n</cross-session-message>`, допускаются пробелы по краям),
в `ChatEntry.Text` кладётся `<body>` с обратной заменой экранирования `<\/` → `</`
(см. `socketmsg.Envelope`). Парсер конверта живёт в `internal/socketmsg` рядом с `Envelope`
(`Unwrap(s string) (body string, ok bool)`), чтобы формат знал один пакет.

Следствия:
- сообщение человека (`from-name="rocket"`) даёт ровно тот текст, что вернул
  `POST /v1/messages` → оптимистичный пузырь подтверждается;
- сообщение агента уже содержит `[from X]` внутри тела → обычный `from`-пузырь;
- вложенные инжекты (`[rocket …]`, `[#…/Q… reply from …]`) внутри конверта классифицируются
  клиентом как обычно.

Не конверт или битый конверт (нет закрывающего тега, лишний текст снаружи) — текст остаётся
как есть. Форма ответа `/v1/sessions/{id}/chat` не меняется; `docs/13-chat.md` дополняется
абзацем «конверт сокета разворачивает демон».

Тесты (Go, таблица): человек, агент с `[from X]`, тело с `</…>` внутри (экранированное),
многострочное тело, незакрытый конверт, текст до/после конверта, обычный текст.

### 1.2 Веб: одна строка

`web/src/lib/classifyUserEntry.ts`: к системным добавить кадры тредов `[#N/QM …]` и
`[<role>/QM …]` (регэксп `^\[#?[\w-]+\/Q\d+ `). Сейчас они рисуются как сообщения человека.
Тест в `classifyUserEntry.test.ts`.

### 1.3 Мобилка: догнать веб

- **`src/lib/chatDisplay.ts`** — классификатор приводится к вебу: системные — `<task-notification>`,
  `<system-…`, `[SYSTEM NOTIFICATION - NOT USER INPUT]`, `[large message]`, `[task #`,
  `[rocket` (включая heartbeat), кадры тредов `[#N/QM …]` / `[role/QM …]`; `[from X]` — агент;
  остальное — человек. Ярлык свёрнутой строки: `<summary>` или первые 60 символов (как веб).
- **Инструменты** — порт `web/src/lib/toolDigest.ts` в `src/lib/toolDigest.ts`: одиночный вызов
  → строка `▸ Bash  git status` (`command` / `file_path` / `description`), 2+ подряд →
  свёрнутая группа «N tool calls». Пара `AskUserQuestion` + `quiz_answer` → существующий
  `ClosedQuizCard` (ask-половина не рисуется отдельно).
- **Отправка** — после успешного `POST /v1/messages` тело оптимистичного пузыря заменяется на
  `res.body` (как веб), чтобы совпадение по тексту работало и для тел с вложениями.
- **Пузыри человека** — через `Markdown`, как ассистент.
- **Кадры тредов** `[#N/QM … from X]` — видимая компактная строка «Q&A #N/QM · reply from X»
  с телом (не шум: это часть разговора).
- **`[large message]`** — указатель, появившийся после отправки, подтверждает её и рисуется
  на своём месте текстом, который отправили (иначе пузырь висел внизу навсегда).

Тесты в `mobile/__tests__/` / рядом с `src/lib`: классификатор (все форматы выше), toolDigest,
`buildChatRows` — подтверждение по `res.body`.

## Часть 2. Вкладка «Вопросы»

### 2.1 Навигация

`app/(tabs)/_layout.tsx`: вкладка `questions` вместо `system`; бейдж = число тредов
`status==='open' && your_turn`. Экран «Система» переносится в стек (`app/system.tsx`) и
открывается строкой «Система» в `(tabs)/settings.tsx`.

### 2.2 Данные

- `src/api/types.ts`: `ThreadInboxEntry` (как `web/src/lib/types.ts`), поле `title` у
  `Question` / `AgentQuestion`.
- `src/api/queries.ts`: `useThreads()` → `GET /v1/threads`, ключ `[baseUrl, 'threads']`.
- `src/api/events.ts`: события `task.question_*` и `agent.question_*` дополнительно
  инвалидируют `threads`. Мутации ответа/отклонения — тоже.
- `src/lib/questions.ts` — чистые функции (порт `web/src/screens/questions/model.ts`):
  `mine` = open && your_turn, сортировка stale-first, затем по `updated_at` по возрастанию;
  `others` = остальные open; подпись источника (`#1023 · <task_title>` / `агент <role_id>`).

### 2.3 Экран `app/(tabs)/questions.tsx`

Сверху вниз: секция «Waiting on you», свёрнутая секция «Other open (N)», пустое
состояние. Pull-to-refresh. UI мобилки англоязычный — подписи на английском.

### 2.4 Карточки

- `src/components/ThreadCard.tsx` — карточка вкладки: источник (тап → `task/[id]` или
  `agent/[id]`), кто спросил, `title`, `body` через `Markdown`; кнопки `options` (тап →
  `{choose: i+1}`, закрывает тред); поле ответа (`{body}`); «Not relevant» (`{dismiss:true}`).
  Адрес ответа: `kind==='task'` → `POST /v1/questions/{id}/answer`, `kind==='role'` →
  `POST /v1/agent-questions/{id}/answer`.
- `src/components/QuestionText.tsx` — заголовок + markdown-тело; им заменяется сырой
  `<Text>{q.body}</Text>` в существующих карточках задачи и агента. Сами эти карточки
  (обсуждение, reply, адресаты) не переписываются — это отдельная, более рискованная работа
  без выгоды для этой задачи.

### 2.5 Отмена (5 с)

`src/lib/deferred.ts` — порт `web/src/screens/questions/deferred.ts`. После действия карточка
сворачивается в плашку «Отвечено: … · Отменить»; запрос уходит через 5 с. Уход с экрана или
сворачивание приложения (`AppState` → background) — немедленная отправка всех отложенных.
Ошибка сервера — карточка возвращается, toast с текстом ошибки.

Тесты: `questions.ts` (фильтр, порядок, подпись), `deferred.ts` (отмена, таймаут, flush),
`QuestionCard` (choose/dismiss/body → правильный URL и тело).

## Порядок работ

1. Демон: `socketmsg.Unwrap` + разворот в чате (+ docs/13-chat.md).
2. Веб: кадры тредов в классификаторе.
3. Мобилка, чат: классификатор, toolDigest, `res.body`, markdown.
4. Мобилка, вопросы: типы и запросы → `questions.ts`/`deferred.ts` → `QuestionCard` →
   вкладка и перенос «Системы» → замена карточек в задаче и агенте.

Проверка: `go test ./...`, `web` и `mobile` — `npm test` / `tsc`; ручная — открыть чат агента
на симуляторе, отправить сообщение, ответить на вопрос кнопкой и отменить.
