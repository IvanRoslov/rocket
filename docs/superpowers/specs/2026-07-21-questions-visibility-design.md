# Questions visibility & screenshots — design

Дата: 2026-07-21. Статус: утверждено устно, ждёт ревью спеки.

## Проблема

Открытые вопросы оркестраторов невидимы, пока не откроешь конкретную задачу:
на канбан-карточке индикатора нет (пропущен из-за N+1, см. комментарий в
`web/src/screens/kanban/TaskCard.tsx`), сводного списка вопросов нет вообще.
Внутри треда страдает форматирование: контекст вопроса рендерится
моноширинной «простынёй» без переносов, а реплики — наоборот, с огромными
вертикальными отступами. Наконец, в вопросы и чат нельзя вставить скриншот.

## Объём

Четыре независимых улучшения, один спек:

1. Индикатор открытых вопросов на карточке канбана.
2. Глобальная страница «Questions» со всеми открытыми вопросами всех
   проектов, с ответами прямо на месте.
3. Починка форматирования тредов (CSS + промпт оркестратора).
4. Вставка скриншотов через Ctrl+V в формах вопросов и в чате.

Вне объёма: mobile-приложение; вложения не-картинки; drag&drop файлов.

## 1. Индикатор на канбане

**API.** `GET /v1/tasks?board=true` (и plain list) обогащает каждый
`taskResponse` двумя полями:

- `open_questions` — число открытых вопросов задачи;
- `questions_awaiting_user` — сколько из них ждут ответа человека
  (`whose_turn == "user"`).

Считается одним запросом на весь список: store-метод
`OpenQuestionCounts(taskIDs []int64) (map[int64]QuestionCounts, error)` с
`GROUP BY task_id`, где «чей ход» выводится по автору последней записи треда
(та же логика, что `whoseTurn` в `internal/api/questions.go`, но на SQL:
вопрос без сообщений от оркестратора → ход человека, от человека → ход
оркестратора; последнее сообщение аналогично). Никакого N+1.

**Web.** В `TaskCard` под строкой оркестратора появляется бейдж:

- есть `questions_awaiting_user > 0` → жёлтый (`tone="warn"`)
  `? N awaiting you`;
- иначе при `open_questions > 0` → нейтральный `? N open`.

Комментарий-заглушка про пропущенный индикатор удаляется. Тип `Task` в
`web/src/lib/types.ts` получает оба поля.

## 2. Глобальная страница «Questions»

**API.** Новый эндпоинт `GET /v1/questions?status=open` — вопросы всех задач
всех проектов. Каждый элемент — обычный `questionResponse` плюс:

- `task_id`, `task_title`;
- `project_id`, `project_name`;
- `orchestrator_name` — имя сессии-оркестратора задачи (для подписи
  «кто спрашивает»), пустая строка, если сессии нет.

`status=open` — единственный поддерживаемый фильтр на старте; без параметра —
тоже только открытые (страница других не показывает, YAGNI). Роут регистрируется
в `registerQuestionRoutes`.

**Web.** Страница `/questions` внутри `AppShell`; в шапке новый пункт
«Questions» между Kanban и System с бейджем-счётчиком вопросов «awaiting you»
(жёлтый, скрыт при нуле). Счётчик и список обновляются по существующим
SSE-событиям `task.question_asked|replied|reopened|resolved` (инвалидация
query `['questions','open']`).

Структура страницы:

- секция **Awaiting you** — треды, где ход человека;
- секция **Awaiting orchestrator** — остальные открытые;
- пустое состояние «No open questions».

Каждый тред — существующий `ThreadCard` из `QuestionsTab`, над ним строка
контекста: `{project_name} · #{task_id} {task_title}` — ссылка на
`/p/{project_id}/tasks/{task_id}`. `ThreadCard` выносится из `QuestionsTab.tsx`
в отдельный модуль `web/src/screens/questions/` — или общий
`components/QuestionThread.tsx` — чтобы обе страницы его переиспользовали
без копипасты. Ответ/уточнение/dismiss работают на месте через существующие
мутации (`useReplyQuestion`, `useAnswerQuestion`); мутации дополнительно
инвалидируют `['questions','open']`.

## 3. Форматирование тредов

Три правки:

1. **Контекст** (`QuestionsTab.css`): у `.question-thread__context-body`
   убирается моноширинный шрифт и «кодовый» вид — обычный Markdown-рендер,
   как у body вопроса.
2. **Компактный ритм** (`components/markdown.css`): в `markdown--compact`
   ужимаются вертикальные маргины `p`, `ul/ol`, `li` (примерно вдвое от
   текущих), чтобы реплики с абзацем-на-каждую-строку не растягивались.
3. **Промпт оркестратора** (`docs/prompts/orchestrator.md`): требование
   форматировать body и context вопросов как markdown — списки вместо
   «(1) … (2) …», пустая строка между смысловыми блоками, без простыней
   в один абзац.

## 4. Скриншоты через Ctrl+V

**Хранение.** Файлы на диске + путь в сообщении (выбрано против data-URI в
тексте — очередь доставки избегает больших tmux-паст, и против блобов в
SQLite — агенту всё равно нужен файл на диске).

- Каталог `<home>/attachments` (рядом с `repos`, `worktrees`;
  создаётся в `config.Load`, поле `Cfg.AttachmentsDir`).
- Таблица `attachments`: `id INTEGER PK`, `mime TEXT`, `size INTEGER`,
  `created_at INTEGER`. Имя файла — `<id>.<ext>` по mime.

**API.**

- `POST /v1/attachments` — тело запроса это сам файл (raw body,
  `Content-Type: image/png|image/jpeg|image/webp`), лимит 10 МБ
  (`http.MaxBytesReader`). Ответ `201 {id, url}`, где
  `url = /v1/attachments/{id}`. Другие mime → 415, превышение → 413.
- `GET /v1/attachments/{id}` — отдаёт файл с правильным `Content-Type` и
  долгим `Cache-Control` (содержимое иммутабельно).

**Доставка агенту.** Перед инжектом сообщения в сессию (общая точка —
`deliverToOrchestrator` в questions.go и `handlePostMessage` в messages.go)
демон переписывает ссылки вида `![...](/v1/attachments/{id})` в текст
`[screenshot: <абсолютный путь к файлу>]` — Claude Code открывает картинку
через Read по пути. В самом треде/чате для веба хранится исходный markdown с
`/v1/attachments/{id}`. Функция переписывания — одна, в пакете `api`, с
юнит-тестами.

**Web.**

- Хук `usePasteImage(onInsert)` в `web/src/lib/`: обработчик `onPaste`
  для textarea — берёт первый `image/*` из `clipboardData`, грузит через
  `POST /v1/attachments`, вставляет `![screenshot](/v1/attachments/{id})`
  в позицию курсора. Пока грузится — плейсхолдер `![uploading…]()`,
  при ошибке — плейсхолдер убирается и показывается сообщение об ошибке
  рядом с полем.
- Подключается: reply-форма треда (на странице задачи и на глобальной),
  форма «Ask the orchestrator» на странице задачи, поле ввода чата
  (`ChatScreen`).
- `Markdown` рендерит `img` с `max-width: 100%`, ограничением высоты
  (~360px) и открытием оригинала по клику в новой вкладке.

## Тесты

- **Go**: store `OpenQuestionCounts` (пусто/открытые/чей-ход);
  `GET /v1/tasks?board=true` с полями счётчиков; `GET /v1/questions`
  (обогащение task/project, только открытые); attachments —
  upload happy-path, чужой mime 415, превышение лимита 413, serve с
  Content-Type; функция переписывания ссылок на пути.
- **Web (vitest)**: бейдж на `TaskCard` (warn/нейтральный/отсутствует);
  страница Questions — секции, ссылка на задачу, ответ на месте;
  `usePasteImage` — вставка markdown, плейсхолдер, ошибка; счётчик в шапке.

## Порядок реализации

1. Форматирование (CSS + промпт) — самое дешёвое, сразу видимый эффект.
2. Счётчики на board + бейдж канбана.
3. `GET /v1/questions` + страница + пункт в шапке.
4. Attachments: store/config → API → переписывание при доставке → веб-хук
   и подключение к формам.
