# Прокрутка веб-терминала — план реализации

> **Для исполнителя:** выполнить задачи последовательно, через superpowers:test-driven-development и superpowers:executing-plans. Каждый пункт отмечать после проверки.

**Цель:** при отсутствии mouse tracking в xterm.js переводить колесо и свайпы в управляющие WS-кадры прокрутки tmux, сохранив обычный ввод для программ, управляющих мышью.

**Архитектура:** `termScroll.ts` отвечает только за перевод дельт, накопление дробных строк и кодирование кадра. `TermPanel.tsx` читает текущий режим мыши на каждом событии, подавляет стандартную обработку xterm только при `none`, объединяет целые строки в один кадр на animation frame и очищает обработчики при размонтировании.

**Стек:** React, TypeScript, xterm.js, Vitest, WebSocket.

**Спецификация:** спека v2 задачи #5073 (Code scroll), подзадача #5075.

## Общие ограничения

- Кадр: `{"type":"scroll","lines":N}`; отрицательные строки идут к старому выводу.
- Максимум 1000 строк за одно значение `lines`; ноль не отправляется.
- У программы с mouse tracking поведение колеса и касаний остаётся прежним; режим проверяется на каждом событии.
- Не менять `convertEol`, рендерер xterm, настройки tmux и код демона.
- При `readonly` демон игнорирует кадр; поведение сервера находится вне этой задачи.

## Фокус проверки

- Дельты трекпада 1–4 px: накопить дроби и отправить только целую строку.
- Смена режима мыши в открытой панели: следующему событию соответствует новый режим.
- Колесо в альтернативном экране без mouse tracking: не превращать в клавиши вверх/вниз.
- Свайп одним пальцем: палец вниз прокручивает к старому выводу; при mouse tracking событие не гасится.
- Размонтирование при ожидающем кадре: не отправлять его после cleanup.
