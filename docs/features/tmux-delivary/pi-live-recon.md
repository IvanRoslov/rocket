# Проверка сохранения ввода в Pi 1.4.0

Задача: #5902, подзадача 2 (#5906). Дата: 1 ноября 2026.

## Область проверки

Это предварительная исследовательская проверка до merge задачи 1. Продуктовая интеграция, изменение запуска Rocket и новые API `nativeinput` не выполнялись. Использованы утверждённые документы из commit `6ff5d39` и установленный Pi 1.4.0.

Проверялся только вопрос: сохраняются ли русский однострочный/многострочный черновик и позиция курсора при вызове Extension API `sendUserMessage` в штатном TUI, в idle и во время выполнения другого хода.

## Среда и метод

- Pi: `1.4.0` (`pi --version`).
- Node.js: `v26.5.1`.
- Python: `3.14.4`.
- ОС: `Darwin 25.3.0 arm64`.
- Каждый сценарий запускался в новом изолированном PTY с отдельными `PI_CODING_AGENT_DIR` и `--session-dir` внутри scratch-каталога worktree.
- Использовался явно тестовый provider `probe/deterministic`, реализованный внутри изолированного расширения. Внешние модельные запросы и учётные данные не использовались, глобальные auth/config не менялись. Это не проверка реального DeepSeek provider.
- В PTY вводился черновик, затем курсор перемещался на три позиции влево от конца строки. Состояние штатного `CustomEditor` читалось через read-only probe-обёртку `handleInput`: текст, `state.lines`, `cursorLine`, `cursorCol`, `ctx.isIdle()`. Методы `setText`, `pasteToEditor` и программный submit не вызывались.
- Сообщение передавалось через отдельный probe-сокет вызовом `pi.sendUserMessage(text, { deliverAs: "followUp", expandPromptTemplates: false })`.
- Для busy сначала вручную запускался длинный ход детерминированного provider, затем создавался черновик и отправлялось внешнее сообщение.

Исходный Pi 1.4.0 также подтверждает кодовый путь: `dist/core/agent-session.js:1910-1937` вызывает `prompt` с `source: "extension"` и `streamingBehavior: "followUp"`; `dist/core/agent-session.js:2774-2781` запускает асинхронную операцию без возврата delivered-подтверждения. Поэтому probe фиксирует сохранение ввода и появление сообщения в истории, но не объявляет вызов API доказательством доставки сам по себе.

## Команда

```bash
python3 scripts/probes/tmux-delivary/pty_preservation_probe.py
```

Перед реализацией probe тот же harness был запущен без расширения и ожидаемо не прошёл: сокет не был создан. После добавления изолированного расширения итоговая команда прошла все четыре сценария за 13.751 секунды. Проверка также подтверждает точное состояние idle/busy, версию Pi по фактическому `pi --version`, структуру записей транскрипта и порядок user → assistant → user → assistant в busy.

## Результаты

| Сценарий | Курсор до/после (`line`, `col`) | `isIdle` сразу после API | Вызовы provider | Сообщение в истории | Черновик и курсор |
| --- | --- | --- | --- | --- | --- |
| idle, одна строка | `0,18` → `0,18` → `0,18` | `false` | 1 | ровно 1 | сохранены после отправки и после settle |
| idle, две строки | `1,20` → `1,20` → `1,20` | `false` | 1 | ровно 1 | сохранены после отправки и после settle |
| busy, одна строка | `0,21` → `0,21` → `0,21` | `false` | 2 | ровно 1 | сохранены после followUp и после settle |
| busy, две строки | `1,15` → `1,15` → `1,15` | `false` | 2 | ровно 1 | сохранены после followUp и после settle |

Во всех случаях `text`, `lines`, `cursorLine` и `cursorCol` совпали точно до вызова, сразу после вызова и после возвращения в idle. В busy второй вызов provider подтверждает обработку followUp после текущего хода. Ровно одна запись `type: "message"` с `message.role: "user"` содержит внедрённый текст; количество подсчитано структурным разбором JSONL, а не поиском подстроки. Все тексты — синтетические.

Маленькие sanitized-доказательства сохранены в репозитории: `scripts/probes/tmux-delivary/results/<scenario>/result.json`. Полные `pty.raw`, `events.jsonl`, транскрипты и временные каталоги остаются git-ignored. Финальный `go test ./...` после исследования прошёл все пакеты; продуктовых изменений не было.

## Повторная проверка production bridge после review-исправлений

Дата: 1 ноября 2026. Ветка `feature/tmux-delivary/pi-bridge-cc`, коммиты `cc9bfe3`, `5220040`, `fa03bd5`, `4538d2f`, `62c5838` и обновлённый fixture.

- `scripts/probes/tmux-delivary/native_bridge_probe.py` теперь запускает Pi с `--session-id`, равным ROCKET target, и после старта сверяет `ctx.sessionManager.getSessionId()` наблюдаемого процесса с этим target. Привязка проверяется по фактической истории, а не по env-строке.
- Ограниченный прогон: `reload`, `target-frames`, `foreign-history` — PASS. После финальных review-исправлений (retirement tombstone и строгая валидация accepted) те же три сценария перезапущены повторно — снова PASS; `/reload` не получает ложный tombstone.
- `reload`: после `/reload` повторный запрос с тем же ID не вызвал второй API submit (`injected_count` = 1, число вызовов provider не выросло).
- `foreign-history`: ROCKET target `live-foreign-history`, фактическая история `live-foreign-history-b`. Endpoint не создан, подключение завершилось `ENOENT`, 0 injected и 0 вызовов provider. Это прямая проверка repro из review.

Полная матрица на текущем коде не перезапускалась: сохранённые результаты остальных сценариев относятся к предыдущей версии моста. Это остаётся gap, а не PASS.

Остаются source-only или непроверенными: login/OAuth и прочие ветки `showSelector`; окно задержанного async listener (допускается Spec2); реальные внешние провайдеры и auth; GitHub Actions отсутствуют.

## Вывод и ограничения

Подтверждено: реальный Pi 1.4.0 Extension API в штатном TUI сохраняет исследованные черновики и курсор при `sendUserMessage` в idle и busy с `followUp`. Предварительное условие для будущей интеграции выполнено, блокера по сохранению ввода не найдено.

Не проверялись: реальный DeepSeek, платные/внешние модельные ответы, dialogs/compaction, разрыв соединения, restart Rocket, restore/kill/switch Pi, дедупликация ID, oversized frames и production UDS lifecycle. Их нужно выполнить после получения merged task-1 contract и явного разрешения оркестратора. Этот документ не разрешает production launch и не подтверждает delivered-семантику моста.
